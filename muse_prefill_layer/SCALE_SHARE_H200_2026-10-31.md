## Implementation and local evidence

The previous encoding proof is now implemented in actual torch weight
repacking, BF16 input gather and GEMM1 shared staging. Gather uses eight
subgroup shuffles and retains two vector stores. GEMM1 retains its original
stmatrix writes, adds one 256-consumer named barrier, then each warp loads a
complete row into registers, synchronizes and writes permuted BF16 pairs.
Original async-proxy fence, publisher synchronization and bulk global copy
remain. NVIDIA documents warp memory ordering for
[__syncwarp](https://docs.nvidia.com/cuda/archive/13.0.3/cuda-c-programming-guide/index.html)
and the required generic/async-proxy ordering before shared-to-global
[bulk copies](https://docs.nvidia.com/cuda/archive/13.0.0/cuda-c-programming-guide/index.html).
These support the synchronization design, not a measured correctness claim. No extra global pass or shared allocation. This is an adaptation of
existing KPERM-style scale reuse, not an original codec.

CPU tests cover 2048 gather words, 147456 staging words/all 65536 raw BF16
patterns and 589824 actual packed bytes/1048576 raw nibbles. Nongated repack
uses full K4096; gated repack covers all8192 rows with reduced K64. Scale
storage is unchanged. Full CPU torch tests use a temporary Mac CPU venv;
no local CUDA execution. An initially missed hoisted scale address and
local duplicate-route/onehot-fixture issues were corrected before GPU launch.
